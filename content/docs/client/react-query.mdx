## Install

```sh
pnpm add @rest-rpc/core @rest-rpc/react-query @tanstack/react-query
```

## Setup

```tsx
import { initReactQueryClient } from "@rest-rpc/react-query";
import { QueryClient } from "@tanstack/react-query";
import { api } from "./contract";

export const queryClient = new QueryClient();

export const rq = initReactQueryClient(api, {
	queryClient,
	baseUrl: "/api",
	getHeaders: () => ({
		authorization: `Bearer ${readToken()}`,
	}),
});
```

The returned object mirrors the HTTP routes in the contract.

## Queries

```tsx
const todo = rq.todos.get.useQuery({
	id: "todo_1",
});
```

Routes without request input can be called with only options.

```tsx
const todos = rq.todos.list.useQuery({
	staleTime: 30_000,
});
```

For request-based routes, falsy request values disable `useQuery()`. This is useful for conditional queries.

```tsx
const todo = rq.todos.get.useQuery(selectedId && { id: selectedId });
```

Traditional way to disable queries remains supported.

```tsx
const todo = rq.todos.get.useQuery(
	{ id: selectedId! },
	{
		enabled: !!selectedId,
	},
);
```

## Suspense Queries

```tsx
const todo = rq.todos.get.useSuspenseQuery({
	id: "todo_1",
});
```

Suspense queries follow normal TanStack Query suspense behavior. 
They cannot be disabled with `enabled` and will therefore not allow falsy request value either.

## Mutations

```tsx
const createTodo = rq.todos.create.useMutation({
	onSuccess: async () => {
		await rq.todos.list.invalidate();
	},
	onError(error) {
		if ("status" in error && error.status === 409) {
			console.log(error.body.code);
		}
	},
});
```

```tsx
createTodo.mutate({
	title: "Write docs",
});
```

## Error Model

React Query uses success and error channels.

Declared 2xx responses become `data`.

Declared non-2xx responses become `error`.

Undeclared responses and runtime errors also become `error`.

This differs from `fetchResponse()`, which exposes declared non-2xx responses as
values.

## Cache Helpers

Each route exposes cache helpers.

```tsx
rq.todos.get.getKey({ id: "todo_1" });

await rq.todos.get.invalidate({ id: "todo_1" });

rq.todos.get.clear({ id: "todo_1" });
```

Use `setData()` to update cached route data without refetching.

```tsx
rq.todos.get.setData({ id: "todo_1" }, (current) =>
	current && current.status === 200
		? {
				...current,
				body: {
					...current.body,
					completed: true,
				},
			}
		: current,
);
```

Query keys are based on the route path in the contract plus request input.
Request fields with `undefined` values are omitted from generated keys.

Pass `queryKey` in query options when a hook needs a custom cache key.

```tsx
const todoKey = ["todos", "detail", "todo_1"];

const todo = rq.todos.get.useQuery(
	{ id: "todo_1" },
	{
		queryKey: todoKey,
	},
);
```

Pass the same key to cache helpers when they need to target a custom-keyed
query.

```tsx
await rq.todos.get.invalidate(
	{ id: "todo_1" },
	{
		queryKey: todoKey,
	},
);

rq.todos.get.setData(
	{ id: "todo_1" },
	(current) => current,
	{
		queryKey: todoKey,
	},
);
```

## Fetch Options

Hook options accept normal TanStack Query options plus `fetchOptions`.

```tsx
const todo = rq.todos.get.useQuery(
	{ id: "todo_1" },
	{
		fetchOptions: {
			cache: "no-store",
		},
	},
);
```

The adapter passes TanStack Query cancellation signals through fetch options.

## Using TanStack Query directly

If you don't like the generated hooks or need specialized behavior, you can always drop down a level.

```tsx
const todoQuery = useInfiniteQuery({
	queryKey: ["todosList"],
	queryFn: async ({ pageParam }) => {
		return await rq.todos.list.fetch({
			page: pageParam,
		});
	},
	initialPageParam: 0,
	getNextPageParam: (lastPage) => {
		if (lastPage.declared && lastPage.status === 200) {
			return lastPage.body.nextPage;
		}
	}
});
```
