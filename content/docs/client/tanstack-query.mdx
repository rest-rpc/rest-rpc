## Install

```sh
pnpm add @rest-rpc/tanstack-query
```

## What It Is

`@rest-rpc/tanstack-query` maps your contract to typed TanStack Query options
and query keys.

Routes expose typed query, mutation, pagination, and key helpers:

```ts
api.todos.get.queryOptions(...)
api.todos.page.infiniteQueryOptions(...)
api.todos.create.mutationOptions(...)
api.todos.get.getKey(...)
```

Plain output streams and routes with exactly one successful streaming response
also expose `streamedQueryOptions()`. See the [Route Builder](/docs/route-builder)
for result forms.

## Setup

```ts
import { createTanstackQueryHelpers } from "@rest-rpc/tanstack-query";
import { api } from "./client-contract";

export const tq = createTanstackQueryHelpers(api, {
	baseUrl: "https://api.example.com",
	getGlobalHeaders: () => ({
		authorization: `Bearer ${readToken()}`,
	}),
});
```

The returned object mirrors the routes in the runtime contract. Use a
[generated contract](/docs/client/contract-generation) for handler-based routes
or import a [separate contract](/docs/contract-first-quickstart).

Client configuration uses the same options as the [Fetch Client](/docs/client/fetch-client),
including global headers, codecs, and optional response validation.

## Queries

Pass generated options to the TanStack Query API for your framework.

```tsx
import { useQuery } from "@tanstack/react-query";

const todo = useQuery(
	tq.todos.get.queryOptions({
		params: { id: "todo_1" },
	}),
);
```

For routes without request input, pass `undefined` if you need to provide options.

```tsx
const todos = useQuery(
	tq.todos.list.queryOptions(undefined, {
		staleTime: 30_000,
	}),
);
```

To disable a query in type-safe way you can use `skipToken` as request input.

```tsx
import { skipToken } from "@tanstack/query-core";

const todo = useQuery(
	tq.todos.get.queryOptions(
		selectedId ? { params: { id: selectedId } } : skipToken,
	),
);
```

You can pass normal TanStack Query options.

```tsx
const todo = useQuery(
	tq.todos.get.queryOptions(
		{ params: { id: "todo_1" } },
		{
			enabled: isReady,
			select: (response) => response.body,
		},
	),
);
```

## Mutations

```tsx
import { useMutation, useQueryClient } from "@tanstack/react-query";

const queryClient = useQueryClient();

const createTodo = useMutation(
	tq.todos.create.mutationOptions({
		onSuccess: async () => {
			await queryClient.invalidateQueries({
				queryKey: tq.todos.list.getKey(),
			});
		},
		onError(error) {
			if ("status" in error && error.status === 409) {
				console.log(error.body.code);
			}
		},
	}),
);
```

```tsx
createTodo.mutate({
	body: { title: "Write docs" },
});
```

## Infinite Queries

Use `infiniteQueryOptions()` when each page should be fetched with route
request input. The query key is inferred from the route and does not include the
request, so every page for the route shares one infinite query cache entry.

`initialRequest` and `getNextRequest` correspond to TanStack Query's
`initialPageParam` and `getNextPageParam`. The rest-rpc helper renames them
because each value must be the full route request input used for the
API call to preserve the request shape.

```tsx
import { useInfiniteQuery } from "@tanstack/react-query";

const todos = useInfiniteQuery(
	tq.todos.page.infiniteQueryOptions({
		initialRequest: {
			query: { status: "open", limit: 50 },
		},
		getNextRequest(lastPage, _allPages, lastRequest) {
			return lastPage.body.nextCursor
				? { query: { ...lastRequest.query, cursor: lastPage.body.nextCursor } }
				: undefined;
		},
	}),
);
```

## Streamed Queries

Use `streamedQueryOptions()` for routes with one successful
`.streamResponse(status, schema)` or a plain `.streamOutput(schema)`. The helper
passes the async iterable to TanStack Query and stores the materialized stream
data. It discards a response envelope when the route uses `.streamResponse()`;
`.streamOutput()` clients return the iterable directly.

:::note
`streamedQueryOptions()` is based on TanStack Query's experimental
[`streamedQuery`](https://tanstack.com/query/latest/docs/framework/react/reference/functions/experimental_streamedQuery)
API.
:::

```tsx
import { useQuery } from "@tanstack/react-query";

const events = useQuery(tq.todos.events.streamedQueryOptions());
```

By default, streamed chunks accumulate into an array.

```ts
events.data;
// Array<{ id: string; message: string }> | undefined
```

Pass `initialValue` and `reducer` when you want a different accumulated data
shape.

```tsx
const messages = useQuery(
	tq.todos.events.streamedQueryOptions(undefined, {
		initialValue: "",
		reducer: (text, event) => `${text}${event.message}`,
	}),
);

messages.data;
// string | undefined
```

## Query Keys

Use `getKey()` when you want the contract-generated key outside an options
object.

```ts
tq.todos.get.getKey({ params: { id: "todo_1" } });
tq.todos.list.getKey();
```

Query keys are based on the route path in the contract plus request input.
Request fields with `undefined` values are omitted from generated keys.

The returned key is typed for TanStack Query APIs.

```ts
const todoKey = tq.todos.get.getKey({ params: { id: "todo_1" } });

const todo = queryClient.getQueryData(todoKey);

queryClient.setQueryData(todoKey, (current) =>
	current && current.status === 200
		? {
				...current,
				body: {
					...current.body,
					completed: true,
				},
			}
		: current,
);

await queryClient.invalidateQueries({
	queryKey: todoKey,
});
```

Pass `queryKey` in options when a query needs a custom key.

```tsx
const todo = useQuery(
	tq.todos.get.queryOptions(
		{ params: { id: "todo_1" } },
		{
			queryKey: ["todos", "detail", "todo_1"],
		},
	),
);
```

Use the same custom key with TanStack Query cache APIs.

```ts
await queryClient.invalidateQueries({
	queryKey: ["todos", "detail", "todo_1"],
});
```

## Fetch Options

Generated options accept normal TanStack Query options plus `fetchOptions`.

```tsx
const todo = useQuery(
	tq.todos.get.queryOptions(
		{ params: { id: "todo_1" } },
		{
			fetchOptions: {
				cache: "no-store",
			},
		},
	),
);
```

The adapter passes TanStack Query cancellation signals through fetch options.

## Error Model

TanStack Query uses success and error channels.

Plain outputs and declared 2xx responses become `data`.

Declared non-2xx responses become `error`.

Undeclared response statuses and other runtime failures become `Error` values in
the error channel.

Direct Fetch client calls return declared non-2xx responses as envelopes instead. See [Fetch Client](/docs/client/fetch-client#call-routes).
