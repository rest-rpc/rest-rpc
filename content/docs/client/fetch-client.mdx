`initClient()` creates a typed fetch client from a contract.

```ts
import { initClient } from "@rest-rpc/core";
import { api } from "./contract";

const client = initClient(api, {
	baseUrl: "https://api.example.com",
});
```

The client has the same route tree shape as the contract.

```ts
const todo = await client.todos.get.fetch({ id: "todo_1" });
```

## `fetch()`

Routes with one successful response expose `fetch()`.

```ts
const todo = await client.todos.get.fetch({
	id: "todo_1",
});
```

`fetch()` returns the successful response body directly.

It throws when the response is undeclared or is not a declared success response.

Use it when non-success responses should use the error path.

## `fetchResponse()`

Every HTTP route exposes `fetchResponse()`.

```ts
const response = await client.todos.get.fetchResponse({
	id: "todo_1",
});
```

`fetchResponse()` returns `status` discriminated union for the response.
Undeclared responses are returned as `rawResponse` with the native `Response` object.

```ts
if (response.status === 404) {
	return;
}

if (response.status === 200) {
	return response.body;
}

response.status; // Exclude<HttpStatusCode, 200 | 404>
response.rawResponse; // Response
```

Set `strictStatusCodes` to `true` on a route factory when `fetchResponse()`
should only return declared status codes and throw on undeclared statuses.
This also narrows the return type to only declared statuses, excluding the `rawResponse` branch.

```ts
const strictRoute = route.with({ strictStatusCodes: true });

const api = {
	todos: {
		get: strictRoute
			.get("/todos/:id")
			.response(200, todoSchema)
			.response(404, notFoundSchema),
	},
};

const client = initClient(api, { baseUrl: "https://api.example.com" });
```

```ts
const response = await client.todos.get.fetchResponse({
	id: "todo_1",
});

if (response.status === 404) {
	return;
}

return response.body;
```

## Client Options

```ts
const client = initClient(api, {
	baseUrl: "https://api.example.com",
	getGlobalHeaders: () => ({
		authorization: `Bearer ${readToken()}`,
	}),
	timeoutMs: 10_000,
	fetchOptions: {
		credentials: "include",
	},
});
```

:::tip
Headers provided by `getGlobalHeaders` make matching declared request headers
optional for client calls. This way you can enforce that client should always
send certain headers without requiring every call to provide them explicitly.
:::

```ts
const api = {
	todos: {
		list: route
			.get("/todos")
			.headers(z.object({ authorization: z.string() }))
			.response(200, z.array(todoSchema)),
	},
};

const client = initClient(api, {
	baseUrl: "https://api.example.com",
	getGlobalHeaders: () => ({
		authorization: `Bearer ${readToken()}`,
	}),
});

await client.todos.list.fetch({});
await client.todos.list.fetch({ authorization: "Bearer override" });
```

## Custom Fetch

If you need to wrap the fetch client with custom logic, pass a `fetch` function.

```ts
const client = initClient(api, {
	baseUrl: "https://api.example.com",
	fetch: async (url, init) => {
		const startedAt = performance.now();

		try {
			return await fetch(url, init);
		} finally {
			console.log("API request took", performance.now() - startedAt);
		}
	},
});
```

## Per-Call Fetch Options

Pass fetch options as the second argument.

```ts
const todo = await client.todos.get.fetch(
	{
		id: "todo_1",
		"x-request-id": "req_1",
	},
	{
		cache: "no-store",
	},
);
```

## Strict Request Keys

By default, unknown request keys are rejected.

```ts
const client = initClient(api, {
	baseUrl: "https://api.example.com",
	strictRequestKeys: true,
});
```

Set `strictRequestKeys` to `false` when extra keys should be ignored before
building the HTTP request.

```ts
const client = initClient(api, {
	baseUrl: "https://api.example.com",
	strictRequestKeys: false,
});
```

## Response Validation on the Client

It is possible to enable server output validation on the client by enabling `validateResponses`.
For understanding the implications of this option, read [Schemas](/docs/contract/schemas/) first.

```ts
const client = initClient(api, {
	baseUrl: "https://api.example.com",
	validateResponses: true,
});
```

This option also validates incoming WebSocket server messages on the client.

## Use in Next.js

When using the core fetch client with Next.js, the client can automatically add deterministic tags to GET
requests through Next's `fetch` options.

```ts
import { initClient } from "@rest-rpc/core";
import { api } from "./contract";

export const client = initClient(api, {
	baseUrl: "https://api.example.com",
	nextFetchTags: {
		enabled: true,
		tagPrefix: "api",
	},
	fetchOptions: {
		next: {
			revalidate: 60,
			tags: ["your-custom-tag"],
		},
	},
});
```

For `client.todos.get.fetch({ id: "todo_1" })`, the client attaches both the
exact request tag and the broader route tag.

```ts
["api:todos.get:id:todo_1", "api:todos.get"];
```

Use the route-level tag for broad invalidation. Use the exact request tag when
the request identifies a stable cache variant.

Automatic tags only include path params and query params. Request bodies are not
included because body-based requests generally should not be cached as GET
fetches. Headers are also excluded because they commonly contain sensitive data,
such as authorization or session values.

You can still pass Next.js fetch options normally through `fetchOptions`.
Generated tags are merged with any tags you provide.

```ts
await client.todos.get.fetch(
	{ id: "todo_1" },
	{
		next: {
			revalidate: 60,
			tags: ["todos"],
		},
	},
);
```

```ts
"use server";

import { revalidateTag } from "next/cache";
import { getNextFetchTags } from "@rest-rpc/core";
import { api } from "./contract";
import { client } from "./client";

export async function renameTodo(id: string, title: string) {
	await client.todos.update.fetch({ id, title });

	for (const tag of getNextFetchTags(
		api.todos.get,
		{ id },
		{ tagPrefix: "api" },
	)) {
		revalidateTag(tag);
	}
}
```

## WebSocket Routes

WebSocket routes expose `openConnection()` instead of `fetch()` and
`fetchResponse()`.

```ts
const socket = client.todos.watch.openConnection({
	id: "todo_1",
});
```

See [WebSockets](/docs/websockets/) for details.
