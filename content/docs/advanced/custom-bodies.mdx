---
title: Custom Bodies
description: Model non-JSON request and response bodies.
---

Default JSON object request bodies are flattened into handler and client input.

Use `customBody()` when the body should be treated as one whole value instead or when the body is not JSON.

```ts
import { customBody } from "@rest-rpc/core";

body: customBody({
	contentType: "image/png",
	schema: z.instanceof(Uint8Array),
}),
```

The handler and client shape is:

```ts
{
	id: string;
	body: Uint8Array;
}
```

## Request Bodies

```ts
export const api = router({
	images: {
		upload: {
			method: "PUT",
			path: "/images/:id",
			body: customBody({
				contentType: "image/png",
				schema: z.instanceof(Uint8Array),
			}),
			responses: {
				204: noBody(),
			},
		},
	},
});
```

```ts
upload({ id, body }) {
	saveImage(id, body);
	return undefined;
}
```

```ts
await client.images.upload.fetch({
	id: "image_1",
	body: new Uint8Array(await file.arrayBuffer()),
});
```

Declare multiple content types when one route accepts the same parsed body shape
under more than one media type.

```ts
body: customBody({
	contentType: ["image/png", "image/jpeg"],
	schema: z.instanceof(Uint8Array),
}),
```

The handler and client body shape includes the selected content type.

```ts
upload({ id, body }) {
	body.contentType; // "image/png" | "image/jpeg"
	saveImage(id, body.payload);
	return undefined;
}
```

```ts
await client.images.upload.fetch({
	id: "image_1",
	body: {
		contentType: "image/jpeg",
		payload: new Uint8Array(await file.arrayBuffer()),
	},
});
```

## Response Bodies

Use `customBody()` in `responses` when the response body has a specific content
type.

```ts
download: {
	method: "GET",
	path: "/images/:id",
	responses: {
		200: customBody({
			contentType: "image/png",
			schema: z.instanceof(Uint8Array),
		}),
		404: z.object({
			code: z.literal("IMAGE_NOT_FOUND"),
		}),
	},
}
```

On the client, a custom response body exposes the raw `Response` object.

```ts
const response = await client.images.download.fetch({
	id: "image_1",
});

const bytes = await response.arrayBuffer();
```

When a custom response declares multiple content types, the server handler
returns the selected content type with the payload.

```ts
download({ id }) {
	const image = loadImage(id);

	return {
		status: 200,
		body: {
			contentType: image.type,
			payload: image.bytes,
		},
	};
}
```

`fetch()` still returns the raw `Response`. `fetchResponse()` also exposes the
matched declared content type on the response envelope.

```ts
const response = await client.images.download.fetchResponse({
	id: "image_1",
});

if (response.declared && response.status === 200) {
	response.contentType; // "image/png" | "image/jpeg"
	const bytes = await response.body.arrayBuffer();
}
```

## Body Parsing

Server adapters do not infer your intended body parsing.

For Express, choose middleware before route execution.

```ts
import { isCustomBody } from "@rest-rpc/core";
import { createRouteMatcher } from "@rest-rpc/express";

const matchContractRoute = createRouteMatcher(api);

const jsonParser = express.json();
const pngParser = express.raw({ type: "image/png" });

app.use((req, res, next) => {
	const match = matchContractRoute({
		method: req.method,
		path: req.path,
	});
	const body = match?.route.body;

	if (
		isCustomBody(body) &&
		(Array.isArray(body.contentType)
			? body.contentType.includes("image/png")
			: body.contentType === "image/png")
	) {
		return pngParser(req, res, next);
	}

	return jsonParser(req, res, next);
});
```

For Hono, use `parseBody`.

```ts
registerRoutes(app, routes, {
	parseBody: async ({ c, body }) => {
		if (isCustomBody(body)) {
			return c.req.arrayBuffer();
		}

		return c.req.json();
	},
});
```
