---
title: Streaming
description: Declare and serve typed Server-Sent Event streams.
---

Streaming routes send Server-Sent Events (SSE). Handlers produce an async
iterable, and each yielded value becomes one event. See
[Serialization and Codecs](/docs/http-behavior/serialization#streams) for the
wire format and [Fetch Client](/docs/client/fetch-client#consume-streams) for
consuming streams.

## Declare a Stream

Returning an async iterable infers a plain stream. Use `.streamOutput()` when
you want to declare and validate its data schema.

```ts
const events = route
	.get("/todos/events")
	.streamOutput(z.object({ id: z.string(), message: z.string() }))
	.handler(async function* () {
		yield { id: "todo_1", message: "Created" };
		yield { id: "todo_1", message: "Completed" };
	});
```

Use `.streamResponse()` when the route can return different HTTP statuses:

```ts
const events = route
	.get("/todos/events")
	.streamResponse(200, z.object({ id: z.string(), message: z.string() }))
	.response(401, z.object({ code: z.literal("UNAUTHORIZED") }))
	.handler(() => ({ status: 200, body: streamTodoEvents() }));
```

Stream schemas describe event data. Event data must be JSON serializable.
Declared schemas validate each value as it is yielded. Once a stream has
started, an invalid value ends the stream instead of producing an error
response.

## Add Event Metadata

Yield data directly when an event does not need metadata. Use `sse()` to add an
event ID, event name, or retry hint:

```ts
import { route, sse } from "@rest-rpc/express";

const events = route.get("/todos/events").handler(async function* () {
	yield { id: "todo_1", message: "Created" };
	yield sse({
		data: { id: "todo_1", message: "Completed" },
		id: "event_2",
		event: "todo.updated",
		retry: 2_000,
	});
});
```

`sse()` throws when `id` or `event` contain line breaks, or when `retry` is not
a non-negative integer number of milliseconds.

## Stop a Stream

The handler's `signal` aborts when the client disconnects. Use it to stop
producing events and release resources:

```ts
const events = route.get("/todos/events").handler(async function* ({ signal }) {
	while (!signal.aborted) {
		yield await nextTodoEvent({ signal });
	}
});
```

## Resume a Stream

A client that reconnects can send the `Last-Event-ID` header. Its value is
passed to the handler as `lastEventId`:

```ts
const events = route
	.get("/todos/events")
	.handler(({ lastEventId }) => streamTodoEvents({ after: lastEventId }));
```

Give events an `id` with `sse()` so clients have a value to resume from.
