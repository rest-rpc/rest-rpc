## Route Context

Route handlers and middleware share a context object that is created for each
request. Use `context.set()` to store values and `context.get()` to read them.

Use `route.$context<T>()` to type the context for a set of routes. Routes built
from the returned builder share that type:

```ts
const authenticatedRoute = route.$context<{
	user: { id: string; name: string };
}>();

const getProfile = authenticatedRoute
	.get("/profile")
	.use(authenticate)
	.handler(({ context }) => context.get("user"));
```

`$context<T>()` is available on the root `route` builder and replaces the
[global context](#global-context) type for routes built from it. For contract-first
routes, call it on the `implement()` result. See
[Contract-first](/docs/contract-first#context-and-middleware).

## Global Context

To avoid having to specify a context type for every route, declare a default
context type for your application globally by augmenting `DefaultContext` in
your adapter package:

```ts
declare module "@rest-rpc/express" {
	interface DefaultContext {
		env: {
			DATABASE_URL: string;
		};
	}
}
```

:::tip
The context type does not guarantee that a value has been set. Set required
values in middleware that runs before any handler or middleware reads them.
See [Middleware](/docs/middleware).
:::
