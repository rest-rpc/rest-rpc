title: Schemas
description: Learn what kind of schemas rest-rpc supports
---

`rest-rpc` accepts schemas that implement the
[Standard Schema](https://standardschema.dev/) spec.

Zod, Valibot, and ArkType are supported Standard Schema libraries. The built-in
`type<T>()` helper provides type-only schemas without runtime validation.

## Request Schema Shapes

Request locations are declared with schema records or whole-location schemas.

:::note
This section describes the default flattened request shape. With
`flattenRequestKeys: false`, clients and handlers receive grouped HTTP request
segments, so whole-location schemas do not need flattened key metadata.
:::

A route builder receives one schema for `params`, `query`, and `body`, while
`.headers()` receives a record keyed by header name.

```ts
route
	.patch("/todos/:id")
	.params(z.object({ id: z.string().uuid() }))
	.query(z.object({ includeCompleted: z.coerce.boolean().optional() }))
	.headers({ "x-request-id": z.string().optional() })
	.body(z.object({ title: z.string().min(1) }))
	.response(200, todoSchema);
```

Each top-level schema property becomes a key in the client and handler request
object.

```ts
await client.todos.update.fetch({
	id: "5f4c6e4e-3f7b-46c7-9fb7-a2e41df03695",
	includeCompleted: true,
	"x-request-id": "req_1",
	title: "Ship docs",
});
```

A whole-location schema validates the whole `body`, `query`, or `params`
object as one value.

For Zod, Valibot, and ArkType, `rest-rpc` can resolve flattened request keys
from object schemas and object-like unions directly.

Zod supports object, union, and discriminated union schemas.

```ts
route
	.post("/items/:id")
	.params(z.object({ id: z.string().uuid() }))
	.query(
		z.union([
			z.object({ q: z.string() }),
			z.object({ page: z.coerce.number() }),
		]),
	)
	.body(
		z.discriminatedUnion("kind", [
			z.object({ kind: z.literal("text"), text: z.string() }),
			z.object({ kind: z.literal("link"), url: z.string().url() }),
		]),
	)
	.response(204);
```

Valibot supports object, union, and variant schemas.

```ts
route
	.post("/items/:id")
	.params(v.object({ id: v.pipe(v.string(), v.uuid()) }))
	.query(
		v.union([
			v.object({ q: v.string() }),
			v.object({ page: v.pipe(v.string(), v.transform(Number)) }),
		]),
	)
	.body(
		v.variant("kind", [
			v.object({ kind: v.literal("text"), text: v.string() }),
			v.object({ kind: v.literal("link"), url: v.pipe(v.string(), v.url()) }),
		]),
	)
	.response(204);
```

ArkType supports object and union schemas.

```ts
route
	.get("/items/:id")
	.params(type({ id: "string" }))
	.query(type({ q: "string" }).or({ page: "string" }))
	.response(204);
```

For other Standard Schema vendors, a whole-location schema needs
`.requestKeys()` when rest-rpc cannot discover its flattened keys.

```ts
route
	.post("/todos")
	.body(type<{ title: string }>())
	.requestKeys({ title: "body" })
	.response(204);
```

Headers are always declared as a schema record with `.headers()`.

## Schema Input And Output

Schemas have an input type and an output type.

| Position                        | Type used     |
| ------------------------------- | ------------- |
| Fetch client request input      | schema input  |
| Server handler input            | schema output |
| Server handler return value     | schema input  |
| Fetch client response value     | schema output |
| WebSocket message send value    | schema input  |
| WebSocket message receive value | schema output |

Default HTTP bodies and WebSocket messages travel over JSON. Path params, query
params, and headers travel through HTTP strings.

## Validation

Server adapters validate incoming request data before calling the handler. The
handler receives schema output.

```ts
const routes = router(api, {
	todos: {
		get({ id }) {
			return getTodo(id);
		},
	},
});
```

Server adapters validate handler output before writing the HTTP response. The
handler returns schema input.

```ts
const api = {
	todos: {
		get: route
			.get("/todos/:id")
			.params(z.object({ id: z.string() }))
			.response(200, todoSchema),
	},
};
```

Fetch clients do not validate response bodies by default. With
`validateResponses: true`, the client validates HTTP response bodies and
incoming WebSocket server messages.

```ts
const client = initClient(api, {
	baseUrl: "https://api.example.com",
	validateResponses: true,
});
```
