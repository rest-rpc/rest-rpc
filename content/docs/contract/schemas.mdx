---
title: Schemas
description: Learn what kind of schemas rest-rpc supports
---

`rest-rpc` accepts schemas that implement the
[Standard Schema](https://standardschema.dev/) spec.

Zod, Valibot, and ArkType are supported Standard Schema libraries. The built-in
`type<T>()` helper provides type-only schemas without runtime validation.

## Schema Input And Output

Schemas have an input type and an output type.

| Position                    | Type used     |
| --------------------------- | ------------- |
| Fetch client request input  | schema input  |
| Server handler input        | schema output |
| Server handler return value | schema input  |
| Fetch client response value | schema output |

Default HTTP bodies travel over JSON. Path params, query params, and headers
travel through HTTP strings.

Request schemas for HTTP string locations and form bodies must declare inputs
that the generated client can serialize. Zod coercion schemas use `unknown` as
their input by default, so specify the generated-client input explicitly:

```ts
route
	.get("/items")
	.query(z.object({ page: z.coerce.number<number>() }))
	.response(204);
```

The `number` generic describes the value accepted by the generated client.
The client serializes it as an HTTP string, and Zod still coerces that string
back to a number when the server validates the request. An unparameterized
`z.coerce.number()` is rejected because its `unknown` input does not guarantee
that the client can safely serialize it.

## Validation

Server adapters validate incoming request data before calling the handler. The
handler receives schema output.

```ts
const routes = {
	todos: {
		get: implement(api.todos.get).handler(({ params: { id } }) => {
			return getTodo(id);
		}),
	},
};
```

Server adapters validate handler output before writing the HTTP response. The
handler returns schema input.

```ts
const api = {
	todos: {
		get: route
			.get("/todos/:id")
			.params(z.object({ id: z.string() }))
			.response(200, todoSchema),
	},
};
```

Fetch clients do not validate response bodies by default. With
`validateResponses: true`, the client validates HTTP response bodies.

```ts
const client = initClient(api, {
	baseUrl: "https://api.example.com",
	validateResponses: true,
});
```
