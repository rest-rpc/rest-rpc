A contract is a plain TypeScript object composed from route builders.

```ts
import { route } from "@rest-rpc/core";
import { z } from "zod";

const todoSchema = z.object({
	id: z.string(),
	title: z.string(),
	completed: z.boolean(),
});

export const api = {
	todos: {
		get: route
			.get("/todos/:id")
			.params(z.object({ id: z.string() }))
			.response(200, todoSchema),
	},
};
```

The contract is used at runtime and at type level. It can drive server handlers,
clients, TanStack Query options, and OpenAPI generation.

## Route Builders

Start a route with an HTTP method and path, then add request and response
declarations with chainable setters. Body, query, and path-parameter setters
each receive one schema.

Use `.response(status, schema)` repeatedly for declared statuses.

## Request Model

```ts
route
	.patch("/todos/:id")
	.params(z.object({ id: z.string() }))
	.query(z.object({ includeCompleted: z.coerce.boolean<boolean>().optional() }))
	.headers(z.object({ "x-request-id": z.string().optional() }))
	.body(z.object({ title: z.string() }))
	.response(200, todoSchema);
```

```ts
await client.todos.update({
	params: { id: "todo_1" },
	query: { includeCompleted: true },
	headers: { "x-request-id": "req_1" },
	body: { title: "Write docs" },
});
```

```ts
const routes = {
	todos: {
		update: implement(api.todos.update).handler(
			({ params, query, headers, body }) => {
				return updateTodo({
					id: params.id,
					includeCompleted: query.includeCompleted,
					requestId: headers["x-request-id"],
					title: body.title,
				});
			},
		),
	},
};
```

## Path Params

Declare a schema for every dynamic path segment with `.params()`.
Both colon-path (`:id`) and curly-brace (`{id}`) syntax is supported.

```ts
route
	.get("/todos/:id")
	.params(z.object({ id: z.string().uuid() }))
	.response(200, todoSchema);
```

## JSON Query

When you need to pass a complex object as a query parameter, you can use `.jsonQuery()`.
The object is serialized to a JSON string and sent as a single query parameter named `query` in the URL.

```ts
const api = {
	search: route
		.get("/search")
		.jsonQuery(
			z.object({
				page: z.number(),
				includeArchived: z.boolean(),
				filters: z.object({
					tags: z.array(z.string()),
				}),
			}),
		)
		.response(200, z.object({ results: z.array(z.string()) })),
};
```

```ts
await client.search({
	query: {
		page: 2,
		includeArchived: false,
		filters: { tags: ["docs", "api"] },
	},
});
```

## Responses

`.response(status, schema)` declares a response body for a status.

```ts
route
	.post("/todos")
	.body(z.object({ title: z.string().min(1) }))
	.response(201, todoSchema);
```

The status is always explicit. Omit the schema argument to declare a response
without a body, such as `.response(204)`.

Call `.response()` once for each declared status code.

```ts
route
	.get("/todos/:id")
	.params(z.object({ id: z.string() }))
	.response(200, todoSchema)
	.response(404, z.object({ code: z.literal("TODO_NOT_FOUND") }));
```

Non-2xx statuses and no-body responses are declared through the same builder
method.

Status-specific response headers can be declared by passing an object containing
`body` and `headers` as the response schema.

```ts
route
	.post("/todos")
	.body(z.object({ title: z.string().min(1) }))
	.response(201, {
		body: todoSchema,
		headers: z.object({
			location: z.string(),
			"x-next-cursor": z.string().optional(),
		}),
	});
```

## Shared Route Options

`route.with()` creates a route factory with shared options for every route built
from it. A factory can share headers, responses, metadata, OpenAPI metadata, and
a path prefix.

```ts
const apiRoute = route.with({
	pathPrefix: "/api",
	metadata: { auth: "required" },
	headers: z.object({ "x-request-id": z.string().optional() }),
	responses: { 401: z.object({ code: z.literal("UNAUTHORIZED") }) },
	openApi: {
		tags: ["Todos"],
		security: [{ bearerAuth: [] }],
	},
});

export const api = {
	todos: {
		list: apiRoute
			.get("/todos")
			.openAPI({ summary: "List todos" })
			.response(200, z.object({ items: z.array(todoSchema) })),
	},
};
```

The route above is normalized to `GET /api/todos`, includes the factory header,
the factory `401` response, and keeps the route-specific OpenAPI summary.

When a route adds its own header schema, both the factory and route schemas
validate the original request headers. Their validated object outputs are
shallow-merged, with route-local properties winning when both outputs contain
the same key. Both schemas remain validation requirements.

## Single Routes

A method on `route` starts one route builder. The result can be exported on its
own; a contract does not need to wrap it in another function or object.

```ts
import { route } from "@rest-rpc/core";

export const getTodo = route
	.get("/todos/:id")
	.params(z.object({ id: z.string() }))
	.response(200, todoSchema);
```
