## Request With JSON Body

```ts
export const api = {
	todos: {
		create: route
			.post("/todos")
			.body(
				z.object({
					title: z.string().min(1),
					labels: z.array(z.string()).optional(),
				}),
			)
			.response(201, todoSchema),
	},
};
```

```ts
export const routes = {
	todos: {
		create: implement(api.todos.create).handler(
			({ body: { title, labels } }) => {
				return { status: 201, body: createTodo({ title, labels }) };
			},
		),
	},
};
```

```ts
const response = await client.todos.create({
	body: { title: "Write docs", labels: ["docs"] },
});

if (response.status === 201) {
	const todo = response.body;
}
```

## Request Without Body

Declare a request without a body by omitting a body setter.

```ts
export const api = {
	todos: {
		list: route
			.get("/todos")
			.query(
				z.object({
					limit: z.number().optional(),
				}),
			)
			.response(200, z.array(todoSchema)),
		byId: route
			.get("/todos/:id")
			.params(z.object({ id: z.string() }))
			.response(200, todoSchema),
	},
};
```

```ts
const implementor = implement(api);

export const routes = {
	todos: {
		list: implementor.todos.list.handler(({ query: { limit } }) => {
			return { status: 200, body: listTodos({ limit }) };
		}),
		byId: implementor.todos.byId.handler(({ params: { id } }) => {
			return { status: 200, body: getTodoById({ id }) };
		}),
	},
};
```

## Request With Form Body

Pass `"application/x-www-form-urlencoded"` to `.body()` for URL-encoded form
bodies.
The body is sent as `URLSearchParams` and then passed to the handler as a
validated object under `body`.

Use a flat object schema whose input fields are strings, numbers, booleans,
arrays of those scalar values, or `undefined`. Array fields use empty-bracket
names such as `tags[]` on the wire. These transport restrictions are not
enforced by the `.body()` schema type.

```ts
import { route } from "@rest-rpc/core";

export const api = {
	forms: {
		submit: route
			.post("/forms")
			.body(
				z.object({
					title: z.string(),
					count: z.coerce.number<number>(),
					remember: z.string().optional(),
					tags: z.array(z.string()).optional(),
				}),
				"application/x-www-form-urlencoded",
			)
			.response(
				201,
				z.object({
					title: z.string(),
					count: z.number(),
				}),
			),
	},
};
```

```ts
export const routes = {
	forms: {
		submit: implement(api.forms.submit).handler(({ body }) => {
			return {
				status: 201,
				body: { title: body.title, count: body.count },
			};
		}),
	},
};
```

```ts
const response = await client.forms.submit({
	body: {
		title: "Write docs",
		count: 3,
		tags: ["typescript", "rpc"],
	},
});

if (response.status === 201) {
	const result = response.body;
}
```

Body parsers should pass a `URLSearchParams` instance to rest-rpc for form bodies.

## Request With Multipart Body

Pass `"multipart/form-data"` to `.body()` for multipart request bodies.
The body is sent as `FormData` and then passed to the handler as a validated
object under `body`.

Use a flat object schema whose input fields are strings, numbers, booleans,
`Blob` values, arrays of those values, or `undefined`. These transport
restrictions are not enforced by the `.body()` schema type.

```ts
import { route } from "@rest-rpc/core";

export const api = {
	uploads: {
		create: route
			.post("/uploads")
			.body(
				z.object({
					title: z.string(),
					file: z.instanceof(File),
					tags: z.array(z.string()).optional(),
				}),
				"multipart/form-data",
			)
			.response(
				201,
				z.object({
					title: z.string(),
				}),
			),
	},
};
```

```ts
export const routes = {
	uploads: {
		create: implement(api.uploads.create).handler(({ body }) => {
			return {
				status: 201,
				body: { title: body.title },
			};
		}),
	},
};
```

```ts
const response = await client.uploads.create({
	body: {
		title: "Write docs",
		file,
		tags: ["typescript", "rpc"],
	},
});

if (response.status === 201) {
	const result = response.body;
}
```

Body parsers should pass a `FormData` instance to rest-rpc for multipart bodies.

## Request With Custom Content Type

For other content types, the schema input must be usable as a Fetch `BodyInit`
value. `application/json` is the exception: rest-rpc JSON-stringifies it.

```ts
import { route } from "@rest-rpc/core";

export const api = {
	imports: {
		csv: route
			.post("/imports.csv")
			.body(z.string(), "text/csv")
			.response(
				201,
				z.object({
					imported: z.number(),
				}),
			),
	},
};
```

```ts
export const routes = {
	imports: {
		csv: implement(api.imports.csv).handler(({ body }) => {
			return { status: 201, body: importCsv(body) };
		}),
	},
};
```

```ts
const response = await client.imports.csv({
	body: "id,title\n1,Write docs\n",
});

if (response.status === 201) {
	const result = response.body;
}
```

## Request With Multiple Custom Content Types

When a request body can be one of multiple content types, declare them in an array.
The client call must specify the `contentType` of the request.

```ts
export const api = {
	images: {
		upload: route
			.post("/images")
			.body(z.instanceof(Uint8Array), ["image/png", "image/jpeg"])
			.response(
				201,
				z.object({
					id: z.string(),
				}),
			),
	},
};
```

```ts
export const routes = {
	images: {
		upload: implement(api.images.upload).handler(({ body, contentType }) => {
			return {
				status: 201,
				body: saveImage({
					contentType,
					bytes: body,
				}),
			};
		}),
	},
};
```

```ts
const response = await client.images.upload(
	{ body: bytes },
	{ contentType: "image/png" },
);

if (response.status === 201) {
	const image = response.body;
}
```
